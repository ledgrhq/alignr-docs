This public site documents selected read operations. The authenticated live schema describes the current Alignr API reference for your deployment, including operations that change data. Retained compatibility operations can be omitted from this reference even when their backend routes remain mounted.

Use an existing [API key](/guides/api-keys) stored in `ALIGNR_API_KEY` for the commands below.

## Retrieve the schema

Alignr generates its OpenAPI reference from the running application. The developer reference is authenticated; it is not an anonymous public schema.

```bash
curl --fail-with-body \
  'https://api.alignr.io/api/v1/developer/openapi.json' \
  --header "Authorization: Bearer $ALIGNR_API_KEY" \
  --output alignr-openapi.json
```

The schema includes `x-ledgr-permission` for route-level permissions and `x-ledgr-destructive` for operations marked as potentially destructive. A null permission extension does not mean an operation is public: authentication and operation-specific checks still apply.

The permission extension does not tell you which credential types a route accepts. A key with a matching write scope can still receive a forbidden response from a route that requires a human session. Many current REST mutations use **My session**; see [Authentication](/api-reference/authentication).

## Inspect authentication and MCP

```bash
curl --fail-with-body \
  'https://api.alignr.io/api/v1/developer/auth' \
  --header "Authorization: Bearer $ALIGNR_API_KEY"

curl --fail-with-body \
  'https://api.alignr.io/api/v1/developer/mcp' \
  --header "Authorization: Bearer $ALIGNR_API_KEY"
```

The MCP reference reports whether the server is enabled and lists tools, arguments and scopes. Use it to confirm the capabilities of the deployment you are connecting to.

## API explorer

Open [Alignr’s developer page](https://app.alignr.io/developer) while signed in for the in-product API reference. Never embed a private key in a documentation site to make an authenticated schema publicly fetchable.

### Run a request in the explorer

Choose **REST API**, filter by path, method, summary or permission, and open an operation. Check **Try it executes as**: use **My session** for human-session routes, or paste a token and select **Use this key** to test a key-compatible operation's actual access. A displayed scope is not proof that an API key is accepted by that route.

Enter the path and query values and review the request body where applicable. When an operation requires **Idempotency-Key**, enter a UUID or select **Generate UUID** once for the intended request. The same value appears in the cURL example and is sent with the request. Keep that key and the identical payload when retrying after a timeout or lost response; generate a new key only for a deliberately new action.

**Execute** sends a read request immediately. Other methods show a confirmation with the method, URL, idempotency key where applicable and body before sending. This operates on your live workspace; it is not a sandbox. Required headers the explorer does not support prevent execution; use an appropriate API client for those operations.

Read the response status and the identity shown beside it. A forbidden response under a narrow key does not establish that your signed-in account lacks access. Pasted tokens are held only for the current page; the explorer does not save them for later visits.

Use **OpenAPI JSON**, **YAML** or **MCP tools** to download the current reference. These downloads describe the deployment; they do not grant access to its operations.
