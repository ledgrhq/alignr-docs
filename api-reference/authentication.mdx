## Bearer authentication

```http
Authorization: Bearer <your-api-key>
```

[Create an API key](/guides/api-keys) with the scopes required by a key-compatible operation. REST scopes use permission codes such as `organization.read` and `detection.read`. MCP uses its own scope names, described in the [tool reference](/mcp/tools).

An API key scope grants permission only where the route accepts API keys. The current API supports scoped keys for the documented read routes and MCP tools, but many ordinary REST writes, including Organization and detection mutations, require a signed-in human session. Issuing `organization.write` or another write scope does not by itself make those routes callable with a key.

## User and service keys

A user-scoped key’s effective permissions are intersected with its owner’s current permissions on every request. Deactivating the owner removes its access. Service keys have assigned scopes and require an expiry.

## Tenant scope

Your credential identifies the tenant: your MSP workspace. Supplying another tenant’s Organization or resource ID does not grant access. Resources outside your tenant are treated as not found.

## Human authentication

The application also uses short-lived session tokens. In the [Developer Console](https://app.alignr.io/developer), choose **My session** for operations that require a signed-in human. Some sensitive actions require additional verification. Step-up authentication is an extra verification step for sensitive actions. An API key does not replace it and cannot obtain a secret-reveal step-up token.

Use the authenticated [live reference](/api-reference/live-schema) to check the requirements for each operation.
