---
title: "Exchange Online certificate access"
description: "Store a customer-owned certificate for a Direct Microsoft connection and request a read-only Exchange connection probe."
---

This API manages a customer-owned certificate for one selected Direct Microsoft connection and requests a fixed, read-only Exchange Online connection probe. It does not collect mailbox data or change Exchange settings. Availability depends on the deployment; confirm the routes in the authenticated [live API schema](/api-reference/live-schema) before use.

Every request uses bearer authentication. Reads require `integration.read`; certificate and operation writes require `integration.manage`. Requests are scoped to the authenticated MSP tenant and the exact client and connection. A foreign or missing resource is returned as not found.

## Prepare Microsoft access

The selected connection must be an enabled Direct Microsoft connection for the Organization. The customer-owned Entra application needs the Exchange Online application permission `Exchange.ManageAsApp` with administrator consent, plus Exchange RBAC that permits the configuration read performed by this probe. These are separate authorization layers; use a suitably scoped Exchange role under your organisation's policy. See Microsoft's [app-only authentication guidance](https://learn.microsoft.com/en-us/powershell/exchange/app-only-auth-powershell-v2) and [RBAC for Applications](https://learn.microsoft.com/en-us/Exchange/permissions-exo/application-rbac).

Microsoft requires the organization's primary `.onmicrosoft.com` domain for Exchange PowerShell's `-Organization` parameter. [Microsoft Graph distinguishes initial from default domain properties](https://learn.microsoft.com/en-us/graph/api/resources/verifieddomain?view=graph-rest-1.0); the current candidate discovers the initial domain, which does not prove it is the Exchange primary domain after a tenant domain change. That case remains unverified; do not infer readiness from saved settings. Require a successful probe whose Exchange-reported tenant and application IDs match the request. Never guess a domain from an email address.

## Read certificate metadata

```http
GET /api/v1/integrations/{integration_id}/exchange/certificate?organizationId={organization_id}
```

Requires `integration.read`. The response contains `active` and `retiring` public certificate metadata (`generation`, `thumbprint`, validity dates and `publicCertificateBase64`). It never returns the private PFX or its password.

## Upload or rotate the certificate

```http
POST /api/v1/integrations/{integration_id}/exchange/certificate
Content-Type: application/json
```

Requires `integration.manage`.

```json
{
  "organizationId": "<organization UUID>",
  "pfxBase64": "<base64-encoded PFX, at most 64 KiB decoded>",
  "password": "<PFX password>",
  "expectedGeneration": "<current generation UUID, when rotating>"
}
```

For a first upload, omit `expectedGeneration`. For rotation, send the generation currently active so a stale form cannot replace a newer certificate. The response contains the public certificate metadata. Upload the returned public certificate to the same Entra application. Keep the old public certificate available while you verify the new one; after a successful probe, retire the previous private certificate with the route below and remove its public certificate from Entra separately.

Treat the PFX and password as secrets. Send them only over TLS through a protected client process and secret manager. Do not put them in shell command history, source control, logs or a ticket. Although the API accepts them in its JSON body, its response and audit record do not contain their values.

To remove the previous stored certificate after rotation:

```http
DELETE /api/v1/integrations/{integration_id}/exchange/certificate/previous
Content-Type: application/json
```

Requires `integration.manage`; send `organizationId` and the currently active `expectedGeneration`. This removes the previous private certificate from Alignr. It does not remove the corresponding public certificate from Microsoft Entra.

## Check saved readiness

```http
GET /api/v1/integrations/{integration_id}/exchange/readiness?organizationId={organization_id}
```

Requires `integration.read`. Readiness reports saved tenant/application configuration, certificate state, required and previously verified checks, and the latest probe receipt. Reading readiness does not start a new Microsoft connection attempt. Use `Cache-Control: no-store` for credential-adjacent operational state; the API sets it on these responses.

## Request and poll a connection probe

Create one probe:

```http
POST /api/v1/integrations/{integration_id}/exchange/operations
Idempotency-Key: <canonical UUID>
Content-Type: application/json
```

Requires `integration.manage`.

```json
{
  "organizationId": "<organization UUID>",
  "certificateGeneration": "<active certificate generation UUID>"
}
```

The operation type is fixed as `connection_probe`; arbitrary PowerShell or cmdlets cannot be submitted. A new request returns `202 Accepted` and a durable operation ID. Poll that exact operation:

```http
GET /api/v1/integrations/{integration_id}/exchange/operations/{operation_id}?organizationId={organization_id}
```

Requires `integration.read`. States are `pending`, `running`, `succeeded`, `failed`, `cancelled` and `interrupted`. The result contains only whether the tenant and application identity checks passed and whether the organization-configuration read succeeded. It contains no mailbox data.

If the create response is uncertain, reuse the same canonical UUID idempotency key with the same authenticated actor, Organization, connection and certificate generation. An identical retry within 24 hours returns the original operation; changed request identity or payload is refused. Use a new key for a new intentional probe. Only one operation can be pending or running for that client connection at a time.

To request cancellation of the exact operation:

```http
POST /api/v1/integrations/{integration_id}/exchange/operations/{operation_id}/cancel?organizationId={organization_id}
```

Requires `integration.manage`. Cancellation of a pending operation is immediate; a running operation receives a cancellation request and may finish before the worker observes it. Poll the same operation to read its final state. Do not create a replacement request while the original is still active.

## What a successful probe means

A successful probe confirms that the isolated runtime connected with the selected tenant and application and could read Exchange organization configuration. It does not prove mailbox visibility, mailbox licensing, message access, data collection, or that any Alignr control passed. Exchange mailbox collection and Exchange setting changes are outside this API's current operation set.
