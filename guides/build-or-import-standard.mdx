Choose the starting point that matches the material you already have. All of these paths still need a review of source coverage and client exceptions before use.

- **Guided domain setup:** For focused questions and relevant sources, open **Standards → Set up a domain**.
- **Standard library:** For a supplied checklist, [choose a baseline](/controls/baselines/overview).
- **Existing questionnaire:** For your team's Excel or CSV checklist, [open checklist import](https://app.alignr.io/standards/import) after signing in.
- **Blank standard:** To define the structure yourself, open **Standards → More → Create a blank standard**.

Creating or importing standards requires `detection_rule.write`. A saved draft is shared standard content; it is not a completed client assessment.

For a scoped assistant workflow, a user-owned key can [copy a curated library template into a disabled draft](/mcp/copy-standard-draft). The owner must retain the appropriate permissions. Review and enable the draft as a signed-in human before running checks; the assistant copy does not evaluate any client.

## Build one domain at a time

Open **Standards → Set up a domain**, or **Choose a domain** in the setup wizard's Standards step. Start with **Identity**, then add other domains when you are ready. Each guided setup creates a separate standard.

The domain chooser lists standards already saved for that domain and whether each is **On** or **Off**. Open one to review it, or choose **Build another** for a separate standard. General or mixed standards remain under **All standards**.

- **Identity:** Choose MFA registration for every enabled account or Global Administrators, and when an unused enabled account needs attention.
- **Devices:** Set how recently managed devices must check in, with optional patch-compliance and MDM encryption checks.
- **Backup:** Set how recent a successful backup must be, alongside reported backup-job errors.
- **Email & domains:** Set instructions and cadence for a human review. This guided path is manual-only and needs no connector.

<Steps>
  <Step title="Answer one question at a time">
    Set the expectation on the current screen, then choose whether to include its check. Leave a check out when it does not fit your policy; an excluded check's answer is not required to continue. Use **Back** to revisit a question. A compact count shows how many checks are selected, and the full list appears at final review. These answers define what you want to assess; they are not evidence that a client meets it.

    For Identity, MFA registration does not prove enforcement at every sign-in. The dormant-account check flags accounts for review; creating the standard does not disable accounts.
  </Step>
  <Step title="Connect your tools">
    Reuse a saved connection or select **Add a connector**. **Browse tools** starts with tools relevant to your domain. Choose another category or **All tools** to widen the list, and search within that selection. **Email & domains** uses a human review and does not need a connector. You can continue without adding a tool and connect it later.

    After saving a connection, use **Match clients** to link its records to the correct Alignr clients. Return to domain setup to continue. A saved connection alone does not prove usable coverage: check its collection status and client mapping.
  </Step>
  <Step title="Review your standard">
    Name the standard and review every proposed check, including which ones are automated or manual. Include only the checks you need; at least one must remain selected. Select **Save inactive standard**. If the save result cannot be confirmed, your answers stay locked. Use **Retry and check standard** to reconcile that same save instead of starting another standard.

    Select **Review & enable standard** to inspect the saved draft before enabling it. Enabling applies it across the workspace, subject to client overrides. Selecting particular clients in **Run checks** does not narrow that activation scope.
  </Step>
</Steps>

Your unfinished answers are saved in the browser and restored when you return with the same account and workspace. Drafts are separate for each domain. A browser draft is not a saved standard. If browser storage is unavailable, saving the standard is paused; restore storage access before continuing.

**Checkpoint:** a named inactive standard contains your intended checks. Confirm source collection and client mapping, review and enable the standard, then run checks. Manual assessments are completed separately.

Use **Set up another domain** when you are ready to add another area. You do not need to configure every domain before assessing the first one.

## Prepare a questionnaire

Use an `.xlsx` workbook or UTF-8 `.csv`, up to **3 MB** and **1,000 question rows**. Include a **Question** column; **Explanation**, **Category**, **Responses** and **Notes** can retain supporting source material. Use values only: spreadsheet formulas are not evaluated and formula cells are rejected. Question and explanation text must each fit within 10,000 characters.

This fictional CSV is a minimal example you can save as `acme-review.csv`:

```csv
Question,Explanation,Category,Responses
Can a representative workload be restored?,Record the recovery point and verify restored data.,Backup,Yes / No
```

“Responses” describes the source questionnaire's response choices. Importing it does not answer the question or record a pass.

## Review the imported questions

<Steps>
  <Step title="Upload the file">
    Open **Import checklist** and select **Choose questionnaire**. Check that the original questions and their source rows are present.
  </Step>
  <Step title="Turn each question into a clear check">
    Choose **Include as a manual check** or **Skip this source question**. For included checks, review the name, instructions, domain, review interval and **Expected passing outcome**. Add a **Review note** explaining scope or interpretation. Skipped questions need an exclusion reason and review note.

    Use **Split into another check** when one question contains separate expectations. A “Yes” answer may mean success or failure depending on the wording; define the intended outcome explicitly.
  </Step>
  <Step title="Resolve review cadence">
    Set **Review every (days)** from 1–730. Bulk cadence mapping can help with groups of source questions, but still needs review. If the source says **Bi-Annual**, explicitly choose its meaning before applying a cadence.
  </Step>
  <Step title="Save progress or create the standard">
    Select **Save progress** to preserve the review. When all rows are reviewed and at least one is included, select **Create inactive standard**. Included check names must be distinct. Open the created standard to inspect it before activation.
  </Step>
</Steps>

The import preserves source lineage and creates **manual check definitions**. It does not create automated predicates or infer client assessment answers.

## If you cannot continue

| Symptom | Recovery |
| --- | --- |
| File rejected | Check format, size, Question header, row count and formulas. Export a values-only copy if needed. |
| Create inactive standard unavailable | Review every row, include at least one check and enter a standard name. Check required outcome, instructions, domain, cadence and review notes. |
| Duplicate check names | Give included checks distinct names that describe their separate scope. |
| Saved import will not load | Use **Retry**. Start a new questionnaire only if you intend a separate import. |

**You should now have:** an inspectable standard with clear expectations and preserved source context. Review [standards and activation](/guides/standards), then [schedule the manual reviews](/guides/client-reviews).
