The Model Context Protocol (MCP) lets a compatible client discover Alignr tools and help resources. Use its tools to list and manage clients, retrieve context, inspect detections and explain control results.

<Tip>Open the [Developer Console](https://app.alignr.io/developer) while signed in to inspect the deployment's MCP tool and scope reference alongside the REST API. Its **Try it** console executes REST requests using your session or, where supported, a scoped API key. **Those requests act on your real workspace**, not an isolated test environment. Connect an MCP client with a scoped API key to read MCP resources or call MCP tools.</Tip>

## Connection

| Setting | Value |
| --- | --- |
| Endpoint | `https://api.alignr.io/mcp/` |
| Transport | Streamable HTTP |
| Authentication | `Authorization: Bearer <Alignr API key>` |

Your deployment must have the MCP server enabled. The trailing slash addresses the mounted transport directly.

## Discover help and tools

After connecting, use your MCP client's resource browser or `resources/list` to find `alignr://help/getting-started` and `alignr://help/tools-and-scopes`. Read either resource with `resources/read`. The first gives connection and workflow guidance; the second lists registered tool names, MCP scopes and required owner permissions from the server's registry. Both return product guidance, not client data, and require a valid bearer key. Reading them grants no tool scope or permission.

Use `tools/list` for the connected server's tool definitions and input schemas. A tool appearing in either list does not mean your key can call it: execution checks its scope and, for user-owned keys, the owner's current permissions. See [Connect an MCP client](/mcp/connect) for Claude Code and Codex examples.

## What you can do

- Retrieve an Organization or list its detections.
- List clients, or create and update a client with a user-owned key and the `organization:write` scope.
- Inspect a client’s compliance grid and explain a control’s status.
- Review a standard across Organizations.
- List curated standard templates, copy one disabled draft with a user-owned key, inspect its full current policy, and activate that exact reviewed draft with a separate user-owned scope and workspace-wide acknowledgement. Activation does not evaluate clients.
- Preview one enabled standard and one client's effective policy, request a durable automated assessment with `standards:evaluate`, and poll the exact historical operation. Evaluation does not collect evidence, assess manual checks or deploy the standard.
- Read a bounded list of remediation run statuses or inspect one run without execution details. Verification remains separate from a completed run.
- Inspect a remediation plan's bounded metadata outline before asking a person to review the actual target and authority. The outline is not a readiness check.
- Preview one exact plan and submit a pending review request with a user-owned key and separate `remediation:preview` and `remediation:request` scopes. A named human still decides the approval; the MCP request does not execute a step.
- Discover evidence sources, request a recoverable source-wide collection with a user-owned `integration:sync` key, and poll its exact SyncRun under `integration:read`. A completed collection is not a passing assessment.
- Inspect persisted PSA/RMM remote-company mappings with `integration:read` and first-link one unassigned record to an existing client with a user-owned `integration:map` key. Linking and source refresh are separate intentions.
- Ask questions over authorised evidence.
- Add a detection note when explicitly granted the write scope.
