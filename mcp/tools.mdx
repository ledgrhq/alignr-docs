Use this catalogue to choose the tool for your question. Names, scopes and defaults are generated from Alignr’s server; [connect your client](/mcp/connect) before making a call.

Confirm deployment availability using the [live reference](/api-reference/live-schema). An Organization is one client in your MSP workspace.

The required scope must be assigned to the key. For a user-scoped key, the owner must also retain the listed user permissions.

## Client context

### Get an Organization

`get_organization`

Fetch summary details for one organization (MSP client).

**Required scope:** `organization:read`

**User permissions:** `organization.read`.

| Argument | Required | Default |
| --- | --- | --- |
| `organization_id` | Yes | — |

- **`organization_id`:** Organization UUID. When optional, omit it to use the tool’s workspace-wide scope.

### Get an asset

`get_asset`

Fetch one asset's non-vaulted field values by ID.

**Required scope:** `asset:read`

**User permissions:** `asset.read`.

| Argument | Required | Default |
| --- | --- | --- |
| `asset_id` | Yes | — |

- **`asset_id`:** UUID of the asset to retrieve.

## Control results

### Read client control results

`get_organization_compliance`

One organization's compliance grid: every control it has been evaluated against, its current status, effective parameters, and when it was last evaluated.

**Required scope:** `compliance:read`

**User permissions:** `detection.read`.

| Argument | Required | Default |
| --- | --- | --- |
| `organization_id` | Yes | — |

- **`organization_id`:** Organization UUID. When optional, omit it to use the tool’s workspace-wide scope.

### Explain a control result

`explain_control_status`

Why one control has the status it has for one organization — the detections raised for a fail, or the specific reason behind a no_data, not_covered or not_applicable.

**Required scope:** `compliance:explain`

**User permissions:** `detection.read`.

| Argument | Required | Default |
| --- | --- | --- |
| `organization_id` | Yes | — |
| `control` | Yes | — |

- **`organization_id`:** Organization UUID. When optional, omit it to use the tool’s workspace-wide scope.
- **`control`:** Control UUID, name, or case-insensitive substring of its name or slug.

### Find clients by control status

`list_organizations_by_control_status`

Which organizations sit at each status for one control, tenant-wide.

**Required scope:** `compliance:rollup`

**User permissions:** `detection.read`.

| Argument | Required | Default |
| --- | --- | --- |
| `control` | Yes | — |
| `status` | No | `null` |
| `limit` | No | `50` |

- **`control`:** Control UUID, name, or case-insensitive substring of its name or slug.
- **`status`:** Status to filter by; the default is shown below.
- **`limit`:** Maximum number of results requested.

### Review a standard across clients

`get_standard_rollup`

How every organization currently stands against one Standard.

**Required scope:** `compliance:standard_rollup`

**User permissions:** `detection.read`.

| Argument | Required | Default |
| --- | --- | --- |
| `standard` | Yes | — |

- **`standard`:** Standard UUID, name, or case-insensitive substring of its name or slug.

## Findings

### List detections

`list_detections`

List detections for the calling tenant, most recently seen first.

**Required scope:** `detection:read`

**User permissions:** `detection.read`.

| Argument | Required | Default |
| --- | --- | --- |
| `organization_id` | No | `null` |
| `status` | No | `"open"` |
| `limit` | No | `10` |

- **`organization_id`:** Organization UUID. When optional, omit it to use the tool’s workspace-wide scope.
- **`status`:** Status to filter by; the default is shown below.
- **`limit`:** Maximum number of results requested.

### Add a detection note

`create_detection_note`

Attach a note to a detection as an evidence row.

**Required scope:** `detection:write`

**User permissions:** `detection.write`.

| Argument | Required | Default |
| --- | --- | --- |
| `detection_ref` | Yes | — |
| `note` | Yes | — |

- **`detection_ref`:** Reference identifying the detection to annotate.
- **`note`:** Text to add to the detection.

<Warning>This tool writes a detection note. Confirm the target and note text before allowing the call.</Warning>

## Search and questions

### Search indexed content

`search_documentation`

Full-text and semantic search over document bodies, asset fields and attachment text (no OCR — images are not indexed).

**Required scope:** `search:read`

**User permissions:** `document.read`, `asset.read`.

| Argument | Required | Default |
| --- | --- | --- |
| `query` | Yes | — |
| `organization_id` | No | `null` |
| `limit` | No | `8` |

- **`query`:** Text to search for.
- **`organization_id`:** Organization UUID. When optional, omit it to use the tool’s workspace-wide scope.
- **`limit`:** Maximum number of results requested.

### Ask an evidence-backed question

`ask_ledgr`

Ask a natural-language question over the governed corpus, with citations.

**Required scope:** `ask:use`

**User permissions:** `document.read`, `asset.read`, `organization.read`, `fact.read`, `detection.read`.

| Argument | Required | Default |
| --- | --- | --- |
| `question` | Yes | — |
| `organization_id` | No | `null` |

- **`question`:** The question you want answered from available evidence.
- **`organization_id`:** Organization UUID. When optional, omit it to use the tool’s workspace-wide scope.

## Understand the answer

A missing result is not proof that a control passed. Read [control statuses](/guides/control-status), retain the client and evidence context, and review [MCP permissions](/mcp/security).
